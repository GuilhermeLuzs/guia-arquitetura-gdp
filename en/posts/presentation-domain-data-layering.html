Presentation Domain Data Layering

Martin Fowler

Read the original post

1. Core idea

The post “Presentation Domain Data Layering” by Martin Fowler addresses the division of an IT system into layers, focusing first on the presentation, domain and data layers and, later, on the need for further divisions as a project grows.

The author starts with an example of a layer division he likes to work with, split into a presentation layer (where information is displayed to the user), a domain layer (where logical and arithmetic operations and processing take place) and a data layer (where the interaction with a persistent database happens). He points out that this layered organization makes it easier to focus development on one activity at a time, setting aside the overall complexity of the application while each part is developed separately and narrowing the scope of reasoning to each part.

Fowler also points out that this way of developing helps with code reuse and makes it easier to change the technologies of specific layers, as long as the contracts between them remain consistent. For example, a function or technology changed in the presentation layer can be applied to several interfaces without having to redo all the other layers.

Finally, the author highlights that this three-layer division works up to a certain point because, in more complex systems, even the presentation, domain and data layers start to become confusing as they carry too many functions. In these cases, it is worth breaking these layers down into more layers according to the project’s needs, in order to keep the benefits of this architecture.

2. Advantages and disadvantages

Advantages

  • Focus on the task assigned to each layer, instead of thinking about the whole system at once
  • Easier maintenance or technology changes in one of the layers without rework in the other parts
  • Modules created in one layer can be reused in others

Disadvantages

  • Excessive abstraction if poorly planned, making the application more confusing
  • Steeper learning curve for beginners

3. Impact on project management

Applying presentation, domain and data layers allows a better division of the development team and speeds up the understanding of the project, besides saving resources and reducing the risk that specific maintenance tasks or technology changes in one of the layers affect the whole project. It also improves development efficiency through code reuse and fixes already targeted at specific layers. It may require more adaptation time from a beginner team.
